El panorama

El ciclo del Sprint

El Sprint es el contenedor. Dentro: Planning → trabajo + Daily → Review → Retrospective → próximo Sprint.

Sprint cycle (e.g. 2 weeks)
Por qué eventos

Cada evento es una chance de inspeccionar algo y adaptar. Ese es el punto de Scrum.

03
Evento 1 · contenedor

El Sprint

Un timebox de duración fija (1-4 semanas, siempre igual). Los demás eventos ocurren dentro.

  • No hay cambios que pongan en riesgo la meta del Sprint.
  • La calidad no baja; el alcance se puede aclarar.
  • El Product Backlog se refina según haga falta.
  • Un Sprint se puede cancelar si la meta queda obsoleta (raro).
Práctica

Elige una duración y manténla. Cambiarla siempre rompe el ritmo y la previsión.

04
Evento 2

Sprint Planning

Todo el equipo planifica el trabajo del Sprint. Responde tres preguntas:

🎯

¿Por qué?

La Sprint Goal — lo que hace que este Sprint valga la pena.

📋

¿Qué?

Qué items del Product Backlog entran al Sprint Backlog.

⚙️

¿Cómo?

El plan para entregarlos y cumplir la Definition of Done.

Timebox

Máx 8 horas para un Sprint de un mes (menos para Sprints cortos).

05
Evento 3

Daily Scrum

Un evento diario de 15 min para que los Developers inspeccionen el progreso hacia la Sprint Goal.

buenas preguntas del Daily
# No es reporte al jefe. Es sincronización del equipo.
- ¿Avanzamos hacia la Sprint Goal?
- ¿Qué haré hoy para ayudar a la meta?
- ¿Tengo algún impedimento?
No es reunión de status

Es para que los Developers planifiquen las próximas 24h, no para reportar a un manager.

06
Evento 4

Sprint Review

El equipo muestra el Increment a los stakeholders e inspecciona el producto juntos.

  • El PO explica qué está Done y qué no.
  • Los Developers muestran el Increment que funciona.
  • Juntos discuten qué sigue y adaptan el backlog.
Práctica

Muestra software funcionando, no diapositivas. Una demo vale mil reportes.

07
Evento 5

Sprint Retrospective

El equipo se inspecciona A SÍ MISMO — cómo fue el Sprint, personas, relaciones, proceso, herramientas.

¿Qué fue bien?
→
¿Qué no?
→
¿Qué mejorar?
→
Acciones
Clave

Termina con pocas mejoras concretas para el próximo Sprint. Pocas y hechas ganan a muchas y olvidadas.

09
Trampas

Errores comunes de eventos

🎙️

Daily = reporte de status

Es para que el equipo planee, no para reportar arriba.

🎬

Review = teatro de demo

Sin diálogo con stakeholders = feedback perdido. Conversa, no solo presenta.

🔁

Retro sin acciones

Hablar sin cambiar nada es una sesión de quejas. Termina con acciones.
